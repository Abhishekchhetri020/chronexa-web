What is Vite?

Lesson 1 — One tool to replace your build script, dev server, and bundler

Vite (French for "quick") is a build tool that does three things that build_bundle.sh cannot: a dev server with instant hot-reload, a bundler with minification + tree-shaking, and a plugin system for TypeScript, Tailwind, etc.

Where Chronexa is today

Your current setup in build_bundle.sh:

# Concatenates 168 files. No minification. No source maps.
cat js/ui/state.js js/ui/i18n.js ... > js/bundle.js

Before (current)

  • Shell script concatenation
  • No dev server
  • Manual reload browser
  • 1 MB+ unminified bundle
  • Tailwind via CDN (300 KB extra)
  • No source maps
  • No dead-code elimination

After (with Vite)

  • npm run dev to start
  • Hot reload on every save
  • Minified + compressed output
  • Tailwind as a plugin (no CDN)
  • Source maps for debugging
  • Tree-shaking removes unused code
  • Code splitting (load solver only when needed)

What Vite actually does

Vite has two modes:

1. Dev server (vite / npm run dev)

It starts a local server at http://localhost:5173. When you edit a file, it sends the change to the browser instantly — no page reload. This is called Hot Module Replacement (HMR). You edit CSS and see it change immediately. You edit a JS file and only that module re-runs.

In dev mode, Vite doesn't bundle anything. It serves native ES modules straight from your source files. That's why it's fast — no waiting for a build.

2. Production build (vite build / npm run build)

This does the heavy lifting. Vite uses Rollup (a battle-tested bundler) under the hood to:

  • Minify — remove whitespace, shorten variable names (saves ~60% file size)
  • Tree-shake — eliminate functions you never call
  • Code-split — produce separate chunks for the solver, editor, and print preview so users only download what they need
  • Cache-bust — add hashes to filenames so browsers always load fresh code
  • Compress — output gzip-friendly assets

Plugins are the secret weapon

Vite does almost nothing by default. Everything useful comes from plugins:

  • @vitejs/plugin-vue Vue support
  • @vitejs/plugin-react React support
  • @tailwindcss/vite Tailwind CSS (removes the CDN)
  • vite-plugin-pwa Service Worker generation
  • vite-plugin-static-copy Copy static assets like your existing CSS

For Chronexa, you wouldn't add React/Vue plugins. You'd use @tailwindcss/vite and vite-plugin-pwa — that's it.

The key insight

Vite doesn't care what framework you use. It works with vanilla JS, vanilla HTML, and plain CSS. You can adopt Vite without rewriting any of your existing code.

Here's the minimum migration for Chronexa:

npm create vite@latest chronexa-web -- --template vanilla
npm install

# Install the plugins you actually need:
npm install -D @tailwindcss/vite vite-plugin-pwa

# That's it. npm run dev starts the server,
# npm run build produces dist/ with minified output.

A real-world analogy

Think of build_bundle.sh like packing a suitcase by hand — one item at a time, no compression, and you have to unpack and repack every time you want to change a shirt.

Vite is like having a robot that watches you pick clothes, folds them automatically, compresses them into a vacuum bag, and labels each bag so you know exactly what's inside.

Try it yourself (2 minutes)

Create a test project to see Vite in action:

cd /tmp
npm create vite@latest my-first-vite -- --template vanilla
cd my-first-vite
npm install
npm run dev

Open http://localhost:5173. Now edit main.js — notice the browser updates instantly without reloading. Press Ctrl+C to stop, then run npm run build. Look at the dist/ folder — that's your production output.
